# 开源前的法律与其他义务

这份文件不是法律意见，但列出了**必须处理掉的义务**和**需要你自己拍板的判断**。
全部结论都标了出处，方便你复核。

---

## 一、基座模型：Qwen2.5-7B-Instruct → Apache-2.0

**已核实**（Hugging Face API `cardData.license`，走 hf-mirror 查的，直连 HF 在本机不通）：

```
license: apache-2.0
tags: ['license:apache-2.0']
```

Apache-2.0 允许商用、允许分发衍生模型。**你需要做的**：

1. 仓库里放一份 Apache-2.0 的 `LICENSE` 全文
2. 保留版权声明 —— 加一个 `NOTICE` 文件：

   ```
   本模型是基于 Qwen2.5-7B-Instruct 微调的衍生模型。
   Base model: Qwen2.5-7B-Instruct, Copyright (c) Alibaba Cloud.
   Licensed under the Apache License, Version 2.0.
   https://huggingface.co/Qwen/Qwen2.5-7B-Instruct
   ```
3. **声明修改**（Apache-2.0 第 4(b) 条要求）：写明"在原模型上使用 LoRA（r=32, α=64）做了监督微调，
   训练数据为自建的人格测评解读数据集"。
4. **不要用 Qwen 的商标做背书暗示** —— 可以说"基于 Qwen2.5 微调"，不能说"Qwen 官方出品"。

> 注意：Qwen2.5 系列里 3B 和 72B 是 Qwen 自有许可（Qwen Research / Qwen License），
> **只有 7B 是 Apache-2.0**。如果你以后换基座，许可证要重新确认。

## 三、训练数据：1579 条解读 —— 这一项需要你判断

`data/curated/` 里的 1579 条解读是**机器生成**的（你提供的 DeepSeek-v4.1-flash 接口）。
这是整套东西里唯一需要动脑子的地方，有三个层面：

**1. 版权状态本身是不确定的。** 各国对"纯 AI 生成内容"是否受版权保护尚无统一结论
（美国版权局目前立场是不保护无人类作者的输出）。**这对你其实是好消息**：它意味着
这批数据大概率不构成他人的版权，你可以自由分发。但也意味着**你无法对这批数据主张版权**
——别人复制它你也管不了。这不影响开源，只是别把它当资产宣称。

**2. 生成接口的服务条款要自己过一眼。** 有些厂商的 ToS 限制"用输出训练模型"或要求署名。
你用的是自己的接口，请确认一下它的条款。如果条款干净，这一项就结了。

**3. 无论如何，在数据集卡里如实声明。** 建议原文照抄：

> 本数据集中的 1579 条解读由大语言模型生成，经规则校验器筛除违规样本（大五通过率 77.7%、
> MBTI 93.8%），**未经人工逐条审阅**。数据用于训练人格测评解读模型，不应被视为
> 专业心理评估建议，也不代表任何临床判断。

**"未经人工逐条审阅"这句必须写。** 这不是自谦，是准确性——审阅清单在
`docs/review-checklist.md`，但 1579 条并没有真的逐条过一遍。

## 五、模型怎么发布（Git 仓库 ≠ 模型发布渠道）

**先给结论：模型一定要发布，只是不能放进 Git 仓库。**

这是**技术限制，不是法律限制**。GitHub 单文件硬限 100MB，而
`adapter_model.safetensors` 是 323MB、合并权重每片 3.9GB，`git push` 会直接被拒。
所有开源模型都是这么做的 —— Qwen 的 GitHub 仓库里也没有 15GB 权重，
**权重都放在 Hugging Face**。

### 正确的拆分

| 放哪里 | 内容 | 体积 | 说明 |
|---|---|---|---|
| **Hugging Face 模型仓库** | **LoRA adapter** | **323 MB** | ← **这才是"开源模型"本身，必须发** |
| Hugging Face 数据集仓库 | `data/curated/` | 19 MB | 可选，便于别人复现训练 |
| Hugging Face（可选） | GGUF Q4_K_M | ~4.5 GB | 给「下载就能跑」的人 |
| GitHub | 代码、规格、文档、训练日志 | ~25 MB | **只放链接指向 HF** |

GitHub 的 README 里写这一行就够了，别人一条命令就能用上模型：

```python
model = PeftModel.from_pretrained(base_qwen, "你的用户名/personality-lora-v1")
```

模型卡直接用 `docs/MODEL_CARD.md`（已写好，可直接发到 HF）。

### 为什么那 15GB 合并权重不必发（即使发到 HF 也不划算）

它是 `Qwen2.5-7B-Instruct 的公开权重 + 你的 323MB adapter`，
别人拿 `training/configs/merge_qwen7b.yaml` **五分钟就能自己合出来**。
发 15GB 换来的只是"省一步"，代价是别人多等 40 分钟下载、你多付存储。

真要给开箱即用的体验，发 **GGUF Q4_K_M（约 4.5GB）**：体积只有三分之一，
而且量化后普通笔记本就能跑 —— 这才是"分享给朋友"真正需要的形式。

## 六、许可证怎么选

| 组件 | 建议 | 理由 |
|---|---|---|
| 代码 | Apache-2.0 | 与基座一致，省去兼容性解释；含专利授权条款，比 MIT 更稳妥 |
| 模型权重 | Apache-2.0 | **继承基座的许可，不能选更严的**（否则违反 Apache-2.0 的再分发条件） |
| 数据集 | CC BY 4.0 或 CC0 | CC BY 4.0 要求署名，适合学术引用场景 |

**注意一个常见的坑**：LoRA adapter 是基座的衍生作品，所以**权重部分的许可证不能比
Apache-2.0 更严格**（比如不能用 CC BY-NC 说"禁止商用"，那和基座许可冲突）。
代码和数据集可以另选，但权重必须保持 Apache-2.0 兼容。

## 七、还该补上的一句诚实说明

模型有个已知的边界问题，开源时应该写进模型卡的局限性里：
**它只会在收到结构化分数时工作。** 训练集里全是「已计分 profile → 解读」这一种样本，
没有"没有数据"的负例，所以任何无分数输入都会触发它去编分数。

这个坑在服务层已经用硬闸门堵住了（见 `docs/API.md`），但**模型权重本身仍然有这个倾向**。
开源时如实写出来，比等着别人发现要好。
